# MH-0 CUDA R1-forward output-banding experiment

Date: 2026-09-11

## Result

Splitting the 40 R1-forward output accumulators into two disjoint 20-output
bands reduces the production CUDA kernel from 96 to 64 registers per thread
without spills. Nsight Compute confirms that theoretical occupancy rises from
33.33% to 66.67% and achieved occupancy from 32.48% to 62.69%.

The change is nevertheless rejected. At 4,000 atoms, the R1-forward kernel is
12.79% slower in the Systems timeline and the complete evaluator is 1.27%
slower. The extra pass over edge metadata increases executed warp instructions
by 27.56%, global-load requests by 22.78%, global-load sectors by 13.66%, and
L2 read sectors by 7.09%. The additional work is larger than the latency hidden
by the extra resident warps.

The experimental production switch was removed after measurement. Generation
11 retains the original one-band R1-forward owner and the accepted R1-reverse
source-feature cache.

## Implementations

The baseline assigns one thread to one `(receiver, channel)` owner and keeps 40
FP32 accumulators live across the complete receiver edge loop.

The first candidate partitions the ten radial paths into two sets whose output
counts are both 20. Each path is evaluated in exactly one band, but the same
thread traverses its receiver edges once per band. Spline coefficient,
harmonic, feature, and contraction work are not duplicated; edge indices,
radius/type metadata, evaluation-point setup, and loop control are duplicated.

The second candidate assigns the bands to separate logical thread owners in
the same physical launch. This shortens each logical owner but adds band-index
division/remainder. It compiles at 72 registers per thread without spills and
was rejected by a 4,000-atom screen before a full campaign.

## Kernel profile

Matched Systems captures contain 11 warmup-plus-measured instances. Median
R1-forward kernel time rises from 1.204866 ms to 1.358915 ms for the sequential
two-band candidate, or 12.79%. Other major kernels remain within ordinary
timeline variation.

Focused Compute collection used the same 4,000-atom input, one captured launch,
`--cache-control none`, and identical launch filters. NCU warned that caches
were uncontrolled, so replay durations are diagnostic.

| Metric | One band | Sequential two band | Change |
| --- | ---: | ---: | ---: |
| Registers/thread | 96 | 64 | -33.33% |
| Stack/local spills | 0 / 0 | 0 / 0 | unchanged |
| Theoretical occupancy | 33.33% | 66.67% | +33.34 points |
| Achieved occupancy | 32.48% | 62.69% | +30.21 points |
| Active warps/scheduler | 3.88 | 7.51 | +93.6% |
| Eligible warps/scheduler | 0.30 | 0.54 | +80.0% |
| Cycles with no eligible warp | 76.68% | 73.12% | -3.56 points |
| Compute replay duration | 1.313024 ms | 1.465312 ms | +11.60% |
| Global-load requests | 96.160 M | 118.064 M | +22.78% |
| Global-load sectors | 288.352 M | 327.728 M | +13.66% |
| L2 read sectors | 240.573 M | 257.636 M | +7.09% |
| Executed warp instructions | 525.137 M | 669.869 M | +27.56% |
| Long-scoreboard cycles/issued instruction | 13.112 | 16.815 | +28.24% |

The added warps are mostly waiting on the larger instruction and load stream.
The fraction of warp latency attributed to long scoreboards falls because more
non-memory instructions are executed, but the absolute long-scoreboard cycles
per issued instruction increase. This is why occupancy improves without a
kernel speedup.
